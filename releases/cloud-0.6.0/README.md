# 两类主动详细解读 0.6.0

2026-11-10。Android code20，Mac/Widget build19。官方小米运动健康、手表绑定、RPK与表盘保持；Mac状态栏与组件仍为简洁显示。

动态24h和每日回顾各增加“详细解读”，打开独立报告页面/窗口。**两类都只有主动点击生成才调用模型**；打开、查询、切换、后台刷新和缓存到期都不触发生成。已完成报告直接展示，未知提交只查询，不自动再收费重发。

- 动态解读侧重所选滚动24h的近期变化、确认餐次、恢复过程及活动/心率时序；固定日解读以选中的自然日为锚点，侧重与7/14天及更早历史的比较、重复模式和改善原因。
- 保留原简洁摘要与重点卡，详细正文另含关键解读、原因假设的支持/反证/验证办法、具体调整和对应文献。报告严格绑定父简报的类型、ID和窗口，不把固定日之后的数据混进来。
- 动态最长复用8h、固定日最长24h，这是最长缓存时限，**不是最小生成间隔**。输入更正或补记后可更早主动生成新版；过期或资料有变更仍保留旧结果，直到用户再次主动生成。较早简报的已完成解读可以查看。
- 简洁动态分析的30分钟间隔和原固定日日报调度保持；100%手动要求针对本版新增的详细解读。

两端已覆盖安装：[Android APK](glucose-watch6-0.6.0.apk)、[Mac应用](OttaiMirror-0.6.0.zip)，发布时核对[SHA256SUMS](SHA256SUMS)。覆盖安装沿用原签名与私密配置，不含令牌、实际健康输入、用户照片或真实报告。Mac继续使用同一路径并保持单实例。

本地及Ali Python3.6共99项服务测试、Android策略、Mac模型/网络交互及两端最终构建通过。正式API和两端已升级；真实动态生成、两端显示、来源/数值核对与缓存读取通过。固定日真实模型使用隔离合成30天资料验证长期侧重及24h缓存，未写正式健康库；正式个人每日详细解读仍需有对应每日简报。最终状态见[云接续](../../docs/CLOUD_SYNC_HANDOFF.md)，方法与资料边界见[详细解读依据](../../docs/DETAILED_ANALYSIS_METHOD.md)。

新增`detail_reports`为增量表，保留所有既有资料。GET只读查询，POST明确生成且要求写/分析能力；任务与简报共用串行锁、既有模型通道及总预算，没有新增公开监听端口或提供方Key。新环境按接续文档先备份、迁移，再覆盖两端。
