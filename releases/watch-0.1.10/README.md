# 手表 RPK 0.1.10：恢复原界面与同步逻辑

versionCode 11，同包名、同签名，直接覆盖 0.1.9 试验版，避免降版限制。手机继续 [0.1.11](../0.1.11/README.md)，表盘继续 [0.1.10](../0.1.10/README.md)。

撤回透明窗口、外层容器与延迟绘制门控。入口页编译产物、图标与原 0.1.8 RPK 逐字节一致；`app.js` 除内嵌版本名/编号外一致。源码测试、release 构建与同证书核对通过，用户已完成覆盖安装，Mi Fitness 返回成功码 0。

安装后重启手机镜像进程以重建 SDK 通道，随即 Home/锁屏。旧测量恢复与随后同时间状态更正均完成自动唤起、文件导出、CPU 窗口提前释放和 ACK，约 9.9 秒；用户仅抬腕确认已返回正常表盘、原始时间匹配。回退与重连共同执行，不能据此单独判定试验失败原因。

随后两个原始时间推进的读数均自动投递：通知处理约 8/7 ms、唤起约 8.01 秒、文件导出约 9.70/9.75 秒、ACK 约 9.75/9.81 秒，CPU 窗口匹配导出后提前释放。首条源通知迟于测量约 2.9 分钟，次条原始时间再推进 5 分钟；不能将它们记为两个严格正常周期，也未额外取得这两条的屏显确认。后段手机亮屏，镜像仍在后台；不声称全程锁屏或长期通过。用户已决定暂不继续修改 UI 闪现。

原手机 0.1.11 + RPK 0.1.8 已通过三轮后台自然周期文件导出，其中前两轮由用户确认表盘时间与自动返回；该历史结果不能代替本次覆盖后复验。原 UI 的短暂显示仍可能出现；没有实现透明或无窗口同步。试验归档见 [调研](../../docs/silent-sync-research.md)。

先核对 `SHA256SUMS`，通过 [Mi Fitness 安装](../../docs/install.md)。
