# 0.1.11：后台通知后的投递保障

手机 APK 为 versionCode 12，与既有版本同包名、同证书。先核对 `SHA256SUMS`。手表继续使用 [RPK 0.1.8](../0.1.8/glucose-watch6-0.1.8.rpk) 与 [表盘 0.1.10](../0.1.10/README.md)，不需要重复安装。

- 每次未送达读数的投递尝试申请最长 20 秒的 partial CPU wake lock，保障 8 秒自动唤起回退与发送；匹配当前完整读数身份的文件导出回执会提前释放，服务停止也释放。
- 同一身份持锁期间不会重复续期；超时后，后续启动或重连可重新申请一次窗口。它不是每帧终身仅 20 秒，也不是持续保活。
- 唤起冷却只限制同一完整身份；新测量、数值或趋势修正不会被旧读数的冷却挡住。迟到的旧唤起回调不能清除新会话。
- 增加通知监听连接/断开日志、断开后重绑，以及新通知到达但桥接服务不存在时的恢复尝试。

新增 `WAKE_LOCK` 是 Android 普通权限。上述 CPU 窗口只保护已经进入本进程后的处理，不能代替 HyperOS 厂商冻结豁免。设置与证据边界见 [后台运行排查](../../docs/background-running.md)。

源码测试和独立审查已通过，APK 已安装。数据源恢复后，连续两个新的自然测量周期均完成自动唤起、文件导出与 CPU 窗口提前释放，约 9.6 秒；镜像持续在后台，先 Home/锁屏，后段手机其他应用在前台。第一轮另有普通 ACK 及用户屏显/返回确认，第二轮普通 ACK 在保留日志中未见、目视待确认。连接恢复补传和旧测量状态更正另计，不冒充自然周期。长锁屏、重启后的豁免保持和长期耗电仍待验证，见 [验证记录](../../docs/validation.md)。

不包含账号、配对密钥、私钥或运行时健康日志。
