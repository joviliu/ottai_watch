# 主动详细解读：方法与接续

2026-11-10，0.6.0。当前简报继续保持精炼，详细解读单独保存和展示。

## 生成规则

动态24h和每日回顾均须主动点击“生成详细解读／生成新版解读”。打开入口、切换类型、查询进度、缓存到期、手机后台和服务器定时器都不生成详细报告。原有每日简报的08:15任务保持。

- 动态详细解读缓存最长复用8h；固定日详细解读最长24h。到期只使按钮可用，旧报告仍可读；对应资料/方法有实质更新时可提前主动生成。
- 这不是最小冷却间隔。没有自动更新、自动重试或“到点调用模型”的任务；不确定结果保留查询，同一未过期请求不重复付费。
- 报告绑定所选简报的`reportId`和时段。动态以该滚动24h为对象，优先解释最近餐次、当前变化与短期验证；每日以固定自然日为锚，侧重周级和更早历史中的方向、重复模式及改善原因。两者分别存储，不互相覆盖。
- 生成时冻结输入。固定日排除截止日午夜及之后的CGM、事件和心率；后来补记的该日餐食或资料更正可使旧解读过时，但次日的新读数不混入该日结论。

## 科学内容怎么约束

正文约1800–3000汉字，按实际信息量调整：摘要、3–6个关键解读、0–3个原因假设、1–5项具体建议和相关来源。原因假设必须同时给出本人证据、反向/竞争证据、可区分解释的验证步骤及支持程度；不以百科段落或免责声明填充。

动态优先解释显著餐次与邻近活动：峰值/峰宽、已观察回落、追加进餐、份量/成分未知、活动开始前曲线方向等。每日优先比较完整日、7/14天及更早统计：均值、波动、偏高/偏低、覆盖、来源与生活条件是否具有可比性。历史不足时只解释已有变化，不编造长期改善。

机制推断采用内分泌病例讨论的标准，但不自称实际医生。胰岛素作用、分泌时序或肝糖输出只是竞争解释；没有相关测量，不能把曲线形态说成已测出β细胞/胰高血糖素异常。若提出医学核验，须说明本次什么反复或持续现象支持它，而非给所有人套检查清单。用户诊断、药物、BMI、症状和实验室资料没有提供时保持未知；私密背景可由服务器环境变量`DETAIL_PATIENT_CONTEXT`提供，不进入公开仓库。

## 可复核的输入处理

- CGM沿用确定性时间权重：每点最多5min，不补长缺口；近期原点、前日数据与多窗口指标保留，更早历史使用日/28日汇总与个人完整日基线。
- 确认餐次与曲线候选分开。餐前30min至少3点且跨度10min才取中位基线；邻近1/2/3h只取±7.5min的真实采样，并附实际时刻。观察到的峰不等于真正吸收峰或分泌量。
- 正增量面积只在≤10min的相邻点之间做分段线性正面积积分，不跨缺口；输出实际积分时长。回到基线+0.3的描述性判据要求峰后无>10min缺口、连续3点跨度10min。该算法是产品描述指标，不是已验证的激素或诊断模型。
- 下一餐、4h边界或报告截止会截断餐后观察；未完成不能当作已恢复。同菜名不等于同份量/同烹调，照片热量不当精确摄入。
- 活动历史按实际记录构建，不使用当前同步时钟决定历史状态；手机与HC步数只选一个来源。心率为实际点的15min统计；步数15min、活动能量30min按原区间起点分组，不均摊。跨边界的总量不计入完整窗口，重叠总量不相加；空白不解释为静止。
- 夜间00–06是时钟区段，不自动当作空腹或睡眠。入睡/起床仅使用用户成对标记；稀疏心率不推算睡眠质量或运动强度。
- 输入有明确截断标志，原始资料不删除。上下文最大210KB，整体模型请求最大256KiB；研究引用只从审核目录中选择。

## 主要依据

这些来源支撑解释框架，不验证本应用餐次算法的准确度；报告只展示本次实际用到的来源。

- [ADA诊断标准2026](https://doi.org/10.2337/dc26-S002)：区分实验室诊断与日常CGM观察。
- [Endotext：胰岛素敏感性评估](https://www.ncbi.nlm.nih.gov/sites/books/NBK278954/)及[Kahn等β细胞综述](https://doi.org/10.1210/endrev/bnab021)：分泌和敏感性解释需要相应功能信息。
- [Endotext：胰高血糖素生理](https://www.ncbi.nlm.nih.gov/sites/books/NBK279127/)：肝糖输出与多种调节因素共同影响葡萄糖稳态。
- [PREDICT1](https://doi.org/10.1038/s41591-020-0934-0)：餐食和个体因素共同影响餐后反应，支持个人条件匹配比较。
- [餐后步行交叉研究](https://pubmed.ncbi.nlm.nih.gov/23761134/)及[ACSM运动共识](https://pmc.ncbi.nlm.nih.gov/articles/PMC8802999/)：活动时机可作为个人对照因素，人群证据不直接证明本次因果。
- [睡眠限制实验](https://pubmed.ncbi.nlm.nih.gov/23070488/)：仅当本人睡眠记录支持时考虑相关解释。
- [Shah健康人CGM研究](https://pubmed.ncbi.nlm.nih.gov/31127824/)及[CGM使用共识](https://doi.org/10.2337/dc17-1600)：测量背景与群体描述不能机械变成本人的诊断线。

## 接口与部署

`GET /api/v1/analysis/detail?kind=rolling|daily&reportId=...`只读取；`POST`同路径使用JSON`{kind,reportId}`才生成。READ能力不可触发生成。原`POST /api/v1/analysis`仍必须零字节请求体，与详细解读接口不同。

增量表`detail_reports`保存父报告、冻结上下文、状态和正文；不改写简报。模型沿用SG现有`gpt-6.1-terra`，使用结构化输出和medium reasoning；[OpenAI Docs](https://developers.openai.com/api/docs/models/gpt-6.1-terra)确认支持。上限10000输出token包括推理token，未完成响应不作为成功报告。仍使用原分析relay/worker和49次总安全预算，照片通道保持独立；提供方密钥不离开SG。缓存并不自动消费预算。

部署先做正式备份及隔离迁移，确认旧表内容不变；停旧API后统一切换模块与提示词，不与旧写入者竞争。旧客户端忽略新增字段并继续同步。两端升级保留连接设置、官方运动健康和手表，无需重装表端。

## 验证记录

本地和Ali Python3.6共99项服务测试通过，包含手动触发、角色权限、8h/24h缓存到期、更正后更新、幂等并发、旧报告保留、模型/来源边界、固定日无未来资料、餐次缺口/截断、活动单位及上下文容量。Mac模型/网络交互、Android策略及两端Release构建通过。正式API与两端已升级。动态详细解读从手机主动生成，约49.7s完成并在两端显示；报告5章、2项假设和4项建议，实际数值、时间定义与引用已核对。固定日以30天合成资料通过隔离真实模型测试，约48.1s、3章/2假设/3建议，明确比较7/14天趋势；重复POST未增加调用。正式库不含该合成报告。

Ali限制192MiB/50%CPU的压力测试覆盖365天105120条CGM、100000个HR样本、96段步数/48段能量/80条Unicode事件，峰值121.9MiB；动态/每日上下文约207KB、请求约230KB，构建各约19.5s。未来数据及同步元数据变化未改变固定日上下文。为避免并发叠加，使用已有模型文件锁非阻塞准备详细上下文，锁忙不创建任务；详情读取超时45s，Android总期限60s。

本轮未验证传感器、营养估算或医学推断的临床准确度；正式固定日报仍等待原72h条件，隔离测试不作为个人健康结论。
