# Health Connect 活动接入与手机 0.4.0

2026-11-10。接入官方小米运动健康写入 Health Connect 的运动会话、心率样本与步数区间，供云端血糖时序观察使用。保留官方 `com.mi.health`、既有蓝牙绑定、手表应用和三款表盘，不需要修改版运动健康。

## 数据通路

`Watch / 手机 → 官方小米运动健康 → 系统 Health Connect → 血糖镜像 → Ali → 描述性预处理 → 既有每日/动态24h模型报告 → 手机和 Mac`。

这是读取已有资料的同步模块，不额外采集传感器，不申请位置/路线，不向 Health Connect 写数据。来源只选 `com.mi.health`，保留来源版本、记录方式、设备元数据及原始时间/时区偏移；不能据此假设每条记录都来自手表，运动健康也可能融合手机资料。

## 授权与运行

1. 在官方小米运动健康连接 Health Connect，允许写入运动、心率和步数，完成设备数据同步。
2. 在血糖镜像「运动与心率 → Health Connect 连接与权限」中启用功能，经系统允许三类读取。可只授予部分类型，未授权类型显示未同步。
3. 要在镜像退到后台后继续读取，需要单独允许「后台读取」。未授予或系统不支持时明确显示仅前台读取，不把后台返回空结果当成完整快照。
4. 保留已有云连接配置。手动点「同步最近48小时」可检查首次读取和上传状态。
5. 可随时停用功能或撤销系统权限，后续读取停止；这不自动删除此前上传的历史资料。

原生模块要求 Android 14+；后台功能还检查系统 U 扩展版本至少13及实际权限。当前最近48小时的读取不需要更早历史权限，安装包未申请该权限。其他旧 Android 版本仍可使用既有血糖/手表通路，但此原生模块不可用。

后台通常每15分钟尝试一次，复用既有云任务/JobScheduler机会，受系统调度和来源写入延迟影响，不承诺精确准点。没有新增传感器轮询、GPS或唤醒锁。活动使用独立有界队列与线程，上传10秒连接/15秒读取超时，失败指数退避至30分钟；不会阻塞原血糖/蓝牙同步。

## 时间、完整性与更正

每次按原生 API **记录开始时间**读取最近48小时，所有已授权类型全部分页成功才产生快照；不是“所有与窗口重叠的记录”。服务端也只在同一开始时间窗口内核对删除。首次窗口前就开始的跨界长记录可能缺失，历史更正/删除超出重读窗口后不会自动回查；这个边界会进入分析说明。

上限为4 MiB、10,000条记录、100,000个心率样本、400页、2分钟。超限、超时、权限变化或前台状态不满足时，整次失败，不截断后冒充完整同步，也不删除云端历史。最新完整快照先保存于应用私有原子文件，再幂等上传；旧快照不能覆盖新状态。云连接改变会清理待上传活动快照，端点和令牌以同一份配置读取。

记录 UUID、原始测量时间、修改时间和同步时间分别保存。支持心率零时长、空采样、任意源顺序及同时间多个值：按时间规范排序但不丢真实样本；同时间冲突值不自动融合。重叠或零时长步数不求可靠总量，不把日总步数均摊成分钟活动。正式数据库和健康记录不得进入 Git。

协议、鉴权、接口限制和存储测试见 [server/ACTIVITY.md](../server/ACTIVITY.md)。`POST /api/v1/activity`仅设备上传令牌可写，Mac/组件的只读令牌不能写；GET dashboard保持schema1兼容旧Mac。公开心率时序为明确标注的5分钟实测采样汇总，保留均值/最小/最大/样本数/真实首末采样时间，不假装为连续原始采样。

## 图表与分析

手机采用浅蓝/紫/桃渐变背景、白色卡片和统一字号间距。首页、连接状态、云图表、授权页均分区；云连接设置移入独立弹窗，刷新图标无蓝色底、点击轻转。

血糖图下方的淡紫色带仅表示已记录运动会话，使用同一时间轴。缺测不连接，不把心率升高或短时步数直接画成已确认运动。心率与步数的实际采样/区间分辨率保留，缺失不当作静止。

固定前一自然日日报和手动滚动24h报告都增加本期/前期活动背景：运动前30分钟、运动中、运动后60分钟的血糖统计和覆盖、同段可用心率、候选餐后样波动的时间重叠、真实短时步数区间与粗粒度/重复提示。这些是描述性产品观察窗口，未被当作临床归因窗口。它们帮助核对活动与血糖变化的关系，不能单独证明因果或胰岛素/β细胞/胰高血糖素异常。活动资料变化会更新手动分析快照身份；仅重复读取同样资料不会引发新的同快照付费请求。

方法依据包含 [ADA活动立场声明](https://doi.org/10.2337/dc16-1728)及 [ACSM 2022共识](https://pubmed.ncbi.nlm.nih.gov/35029593/)。后者针对2型糖尿病人群，不将其治疗目标直接套用未确诊成人。完整提示词和既有健康研究/长期比较方法见 [CGM分析方法](CGM_ANALYSIS_METHOD.md)及 [daily_prompt.md](../server/daily_prompt.md)。

### 数据源判断与替代路径

“我的→三方数据管理”是第三方OAuth授权管理/撤销页，[官方云接口指南](https://dev.mi.com/xiaomihyperos/documentation/detail?pId=2333)有明确说明。该页没有HC项不能独立证明本机或国行版禁用了HC。已确认的事实应以系统库、原生读取和上传后的实际来源/测量时间为准。

本机曾通过官方导出的`com.xiaomi.fitness.access.health_connect.HealthConnectIntroductionActivity`打开连接说明，再由用户在系统授权写入；这不修改官方APK或绕过授权。初始没有立即回填历史，不能据此推断永远没有新增资料。国际Mi Fitness的[Google Play说明](https://play.google.com/store/apps/details?id=com.xiaomi.wearable)声明支持HC，但其包名不同，不能代替当前`com.mi.health`实测。

备用方案调研：小米[MiHealthKit端侧接口](https://dev.mi.com/xiaomihyperos/documentation/detail?pId=2330)和[健康云接口](https://dev.mi.com/xiaomihyperos/documentation/detail?pId=2333)支持按时间读取健康样本/运动记录，需申请账号服务、健康服务及权限审批；不是现有XMS通信SDK自动获得的权限。小米[系统计步Provider](https://dev.mi.com/xiaomihyperos/documentation/detail?pId=1603)提供手机传感器计步区间，本机已确认Provider存在、READ_STEPS为normal权限，但未对本应用申请身体活动权限、未读取或上传该来源。Android原生TYPE_STEP_COUNTER也可自行记录，不能从手机计步补出手表心率。用户要求有真实HC数据就不再自采，因此这些备用代码未纳入发布。

### 真实非空资料与兼容修复

原生读取和正式Ali数据库已确认收到来自官方`com.mi.health`3.59.2的非空心率资料，没有向正式库注入合成资料。此前失败是服务端把记录容器的区间结束时间限定在“现在+90秒”，无法接收以未来日界限封装的有效记录。修复只放宽容器上界并保留31天上限；真实样本、修改时间和开始时间仍严格检查，未发生时段不形成观测点。

这说明“本机完全无法向HC写入”的判断不成立。初始空库、尚未立即回填及授权管理页无HC项，只能说明当时没有已共享资料。当前确认的是心率；运动会话和步数尚未收到真实样本，因此不宣称三类数据均已接通。按用户要求，手机自采步数的备用实现已撤回，不新增传感器、计步权限或另一条采集链。
