# 官方小米运动健康与血糖的活动关联：可行性核查

2026-11-10。此页是只读调研和接入方案，不代表活动数据已接入现有云服务。原Android/手表/Mac版本及授权保持；没有替用户开启Health Connect权限或向正式数据库写活动资料。

## 当前设备证据

通过已连接手机的包元数据核查：官方`com.mi.health`为3.59.2/code359002，Android API36。系统有`com.android.healthconnect.controller`及`healthconnect`服务。官方应用包含HealthConnect权限说明Activity，声明`WRITE_EXERCISE`、`WRITE_HEART_RATE`、`WRITE_STEPS`、`WRITE_DISTANCE`、`WRITE_ACTIVE_CALORIES_BURNED`等；本次查询这些运行时写入权限均为`granted=false`。因此已有可用集成线索，但尚无授权后的真实记录/采样粒度/后台同步验证。空的服务dump没有用于推断数据仓库为空。

本项目当前Android镜像未声明Health Connect读取权限，也没有采集模块。既有XMS代码用于手表通信，不能因已有蓝牙绑定就声称可以读取运动健康的历史库。官方APK还声明导出的`com.mi.health.provider.main`，但`exported=true`不证明健康记录可以无条件读取；部分其他provider/权限为签名或系统级。没有验证它的调用协议与内部授权，也不把它当作已可用公开健康API。

本次仅保留去掉设备标识的上述结论。原始包dump/APK仅在本机私密目录，不能将健康记录、账户资料、完整包dump或鉴权信息提交Git。

## 优先接入路径

`Redmi Watch 6 → 官方小米运动健康 → Health Connect → 血糖镜像只读模块 → Ali → 时间对齐/统计 → Mac与AI报告`。

小米的[官方第三方数据说明](https://www.mi.com/global/support/faq/details/KA-728033/)说明Mi Fitness可连接Health Connect；该页面面向另一款穿戴产品，不能单凭它保证Watch6/国行版本输出一致。当前设备的Manifest证据缩小了版本不确定性，仍须实测。

[Google针对Mi Fitness的官方说明](https://support.google.com/googlehealth/answer/14236613?hl=en)列出运动中的心率、活动汇总、总步数/距离等可共享项目，也列出运动外心率、小时/分钟距离等不共享项目。这是Google Health这一路径的兼容说明，不是对所有版本Health Connect原始记录的穷尽保证；不能据此断言所有国行版本全天心率都能导出，也不能把缺数据算为零。

第一轮验证应在用户完成系统授权后，分别抽查：

1. `ExerciseSessionRecord`：运动类型、原始开始/结束时间、记录方式和来源。
2. `HeartRateRecord`：带时间戳样本，尤其区分运动中和运动外；核对手表/应用中确实存在的同一时间段。
3. `StepsRecord`：记录起止与计数，确认它是短时段记录还是日总量。
4. 来源`DataOrigin`、设备元数据、更新时间及回补天数；区分手机与手表数据，防止重复计算。
5. 关闭页面、锁屏后的写入/读取及延迟，不只检查前台同步一次。

[Health Connect数据类型与运动读取](https://developer.android.com/health-and-fitness/health-connect/experiences/workouts)提供按运动会话时间再读取同段心率的标准路径。[后台与历史读取](https://developer.android.com/codelabs/health-connect)需分别验证feature availability并由用户授权；默认历史起点为首次授权前30天，更早历史要单独权限，并非新数据只能保留滚动30天。只申请本功能需要的运动、心率、步数读取；不需要路线/GPS。授权不等于小米已回填全部历史。

若全天心率或旧记录没有写入HC，可使用[小米官方数据导出](https://www.mi.com/ph/support/article/KA-11566/)（账号隐私→管理数据→Mi Fitness→下载）核查并回补已有资料。是否含具体心率字段、分钟采样及全部历史须以真实导出包为准；它不是已验证的持续自动同步接口。

## 运动时段与曲线如何表示

- 已记录运动会话直接画时段条，标类型、起止；自动识别与手动记录保留来源/记录方式。
- 短时段步数加心率可作为「推估活动」的依据，单独标低/中置信度及数据覆盖，先做规则验证，不假称临床验证模型。
- 单独心率升高不能确认运动，也可能受压力、进食、疾病等影响。没有步数不能排除骑行、力量运动；缺测、未佩戴不能当静止。
- 只有日总步数时只做日级活动量比较，不能把总数平均摊到5分钟来制造活动曲线。
- 血糖主图沿用原单位/刻度；活动画下方时段条/独立小图，心率另标bpm。按真实测量时间对齐，保留UTC时间和时区，不用上传时刻冒充活动时间。只按实际采样分辨率展示，不将稀疏心率补成连续实测线。

## AI增加的背景与边界

预处理生成运动前/中/后的血糖统计、覆盖率、时长、类型及实际心率强度证据，并标记与候选进餐波动的重叠。先以30–60min、1–2h等明确标为产品观察窗口作描述，不预设因果或普遍有效窗口。再比较自身相近时段/起始血糖/可用进食记录的多天模式，保留饮食、睡眠、活动类型和采样差异。

[ADA活动/运动立场声明](https://doi.org/10.2337/dc16-1728)与[ACSM2022共识](https://pmc.ncbi.nlm.nih.gov/articles/PMC8802999/)支持把运动类型、强度、时机作为背景考虑，反应会随人群与条件变化；糖尿病/用药人群的结果与建议不能直接套用到未确诊的成人。模型不能预设运动必然降糖，也不能把活动相关上升自动认定为代谢恶化。

目标是减少把活动相关变化误归因于进餐或胰岛素的情况，增强参考解释。即使运动与血糖同步变化，也不证明运动导致变化、饮食不健康，或β细胞/激素功能已发生改变。是否提高个体推断准确度，仍需真实数据和后续验证。

## 开发前置门槛

先完成权限和真实记录小样本验证，确认尤其是全天心率/分钟步数能否读到，再定功能范围。后续开发涉及Android只读/增量队列、Ali独立活动表与幂等接口、按时间/来源的预处理、图表活动层和分析Prompt；本轮没有将这些未实现部分标成完成。
