# 小米运动健康直连与 HC 心率缺口调查

调查日期：2026-11-12。当前仅完成官方文档、应用静态代码及真实链路的只读核对；没有接入新的健康数据通道，也没有修改官方应用、重置手表或重新授予权限。

## 结论

小米存在正式的云对云与端侧数据开放能力，HC 不是唯一通道。但“我的 → 三方数据管理”是第三方授权管理入口，不是所有应用都能直接读取资料的公共 Provider。Keep 出现在该页，不能据此判断其使用新端侧 SDK、数据粒度或同步时延。小米[隐私政策](https://watch.xiaomiwear.com/html/privacy/index.html?locale=zh_cn&model=app&type=sport_healthy_privacy)列出 Keep 的授权共享；[业务介绍](https://dev.mi.com/xiaomihyperos/documentation/detail?pId=2325)另区分云对云和系统本地服务。

本机实时确认 Xiaomi HyperOS `OS3.0.307.0` / Android 16，未安装 `com.xiaomi.healthkit`；官方运动健康已是 `3.61.0 / 361000`，不能继续把旧版 `3.59.2` 静态结果当作当前版本证据。镜像仍为 `0.8.0 / 24`。

## 本次真实链路核对

- 双方所需 HC 读/写权限仍在，镜像后台读取权限仍在；两应用运行时省电豁免均保留。官方设备服务及镜像前台服务存活。本次未取得能归因的冻结或官方 HC 错误日志，不能由日志为空推断没有历史错误。
- HC 中已观察到的一段近千个秒级运动心率采样，已由镜像读取并保存到 Ali；未据此推断手表所有原始采样都已导出。当前整个 48h 快照不到 0.1 MiB，记录数、采样数及大小远低于现有限制，没有分页失败证据。
- 普通心率曾有数小时缺口，而镜像的完整读取快照仍推进。随后系统 HC 原始详情出现新的普通心率，镜像下一后台周期也读到并上传了相同实际采样。因此不是持续的镜像容量耗尽、上传停止或图表去冲突隐藏数据。
- 用户随后核对官方心率页，确认 HC 缺口时段在官方应用中有心率；该页最新测量也新于当时 HC 最新实际采样，系统 UI 已核对官方最新时间。这确认存在官方资料向 HC 的导出缺口或迟写，不能解释为手表在整个缺口期间没有测量；尚未证明密集运动采样是触发原因。
- HC 记录时间、实际采样、源端修改、镜像同步时间分别核对。整次查询成功不代表各类型都产生了新测量；容器结束时间也不代表最后采样时间。服务端活动状态的同步时间来自客户端，不能冒充服务器收包时间。
- HC 新数据在本次打开官方运动健康之前已经存在。本轮没有点官方“连接”或手动同步。用户确认最近十分钟没有操作官方应用，但更早一次源端补写的触发原因仍不能据此确定。

镜像读取完整授权类型后才原子上传，不按旧 `modifiedAt` 跳过心率采样；服务端接受相等修改时间但内容改变的修订，当前实际样本没有时间冲突。相关代码见 `HealthConnectBridge.java`、`HealthPolicy.java`、`ActivityCloud.java` 及 `server/activity.py`、`server/storage.py`。

## 官方 3.61.0 静态线索及边界

仅在仓库外保存本机 APK 和必要摘录，不分发官方 APK 或反编译代码。

1. 普通心率 `HrSyncBiz` 与运动心率 `SportSyncBiz` 是不同业务；运动段写入成功不能证明普通心率队列持续工作。
2. `HealthConnectComponent.checkAndStartSync` 的部分进程启动初始化仍在应用地区为 `cn` 时跳过。显式“连接”路径可以重新注册触发器/监听；但重连不会自动补回所有既有普通心率。
3. 普通心率 pending 窗口聚合和跨窗口查询存在可疑边界；有间隔窗口时可能构造包含窗口外采样的记录。该机制有静态依据，但没有本次异常日志或源端队列证据，不能定为实际根因。

当前 APK 的 `DataContentProvider` 虽然 exported，但另有读取权限、系统/内部签名或包名与签名白名单校验；普通安装的镜像应用不能据此访问官方原始资料。进程内 receiver 也不是可由镜像跨应用广播调用的公开同步 API。

这些代码属于官方应用。镜像不能通过修改自身读取逻辑修复官方数据库触发器、进程内广播或 HC 写入队列；也不应以高频重开应用、后台反复点击授权代替修复。

## 后续验证与可实施条件

出现下一次缺口时，先保留现场，对照官方应用实际心率、系统 HC 原始采样及 Ali 原始采样；先不要重连或手动同步。只有 HC 已有而镜像缺失，才继续修复镜像读取、来源过滤或错误处理；HC 本身没有时，应检查官方设备同步/导出与触发条件。

若申请小米云接入成功，适合在 Ali 增加独立 OAuth 来源，凭据留服务端，按小窗口增量读取并校验变更通知。新增来源必须与 HC 隔离保存、明确来源优先级，不能把同一手表的两份记录叠加。获批前不发布无法工作的“直连已支持”开关，不借用 Keep 的身份或令牌。
