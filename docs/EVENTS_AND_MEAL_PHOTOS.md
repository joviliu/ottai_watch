# 重点分析、生活标记与餐食照片

2026-11-10，0.5.0。手机与Mac使用同一份血糖/活动资料和生活标记，原官方运动健康、手表应用与表盘保留。

## 报告怎么读

主报告按「最值得关注的现象 → 与自身历史的变化 → 可执行建议」组织为少量重点卡片，标题加粗，以背景颜色区分关注、一般观察和正向变化。不会逐点抄写图中时间/基线/峰值/下降分钟，也不在每章重复通用免责声明。仅对会改变当次结论的资料缺口作简短说明。

研究依据按相关主题折叠，已介绍的基础知识不反复展开；保留有助解释新现象的内容。历史较短时不捏造长期比较，只有候选波动时用简短的「疑似餐后」而不冒充确认餐次；这些约束留在分析方法中，不变成长篇套话。原始统计和详细历史仍保留。

动态24h和固定前一自然日日报各自存储、在同一文字区切换。手机新增与Mac一致的手动动态分析入口，沿用最近24h完整性、30分钟最小调用间隔、同快照复用和不确定结果不自动重发的既有规则。

## 时间标记

Mac主图悬停显示时间竖线和时间标签，点击后可选进餐、入睡、起床、运动或备注，时间可调整。手机在图上选时采用类似流程，并保留纵向滚动。已有标记可打开修改或软删除；冲突不默默覆盖另一端的新内容。

事件以毫秒时间戳和独立ID保存，可附备注。进餐另有食物文字、估算热量下/上界及来源；没有热量是未知，不能当0。存储区分用户确认的近似进餐时刻与曲线候选。睡眠需入睡/起床配对，不把一个点编成完整睡眠时长。所有记录作为数据，不作为给模型的指令。

事件摘要进入动态/固定报告及快照身份；补记后不会继续复用未包含该记录的同快照结果。正文只使用有记录支持的餐次名称。模型使用有界上下文并标明截断，原始记录不因压缩上下文而删除。

## 手机餐食照片

选进餐后可以手动填写食物，也可拍照或选已有图片，点击识别后才调用模型。识别返回可修改的食物/大致份量与千卡范围；确认保存后才成为进餐记录，不自动把照片推测写成实际摄入。

手机先按EXIF方向旋转/翻转，再压缩为最长边1024px、最多1024²像素、最多1MiB的JPEG并去元数据。相机只获得单个临时URI访问权，应用不申请全相册读取或直接相机运行时权限。临时文件按编辑生命周期清理；服务端校验真实JPEG头、尺寸与请求体，不接受任意远程图片URL。

照片通过 Ali → 专用SG worker → OpenAI，提供方密钥仅在SG通过systemd credential加载。请求体只在执行线程/队列内存，不进健康记录数据库或访问日志；数据库保留请求摘要、状态、结果与用量。确认后保存食物/热量及来源，不保存照片。

识别为显式异步请求：客户端保留requestId，断网后查询同一任务，不自动重发付费调用；未知结果不自动再收费重试。食物识别预算与血糖分析独立，默认每日30次，至多一个有效执行任务；日报/动态分析的既有49次上限不受它挤占。错误响应不转存可能回显图片或凭据的上游原文。

## Token与费用

使用现有 `gpt-6.1-terra`，不为照片更换现有血糖分析模型。依据[官方模型说明](https://developers.openai.com/api/docs/models/gpt-6.1-terra)及[价格页](https://developers.openai.com/api/docs/pricing)，2026-11-10 Standard短上下文价格为每百万输入token $1、输出token $5、缓存输入token $0.05。图片输入支持与API格式见[官方视觉指南](https://developers.openai.com/api/docs/guides/images-vision)。

界面显示实际返回的输入/输出token与基于上述费率的美元估算。官方当前图像分块表没有明确列出本模型的专用乘数，因此不把某个像素公式硬套成确定费用。若实际usage缺失或不一致，显示用量未确认，不冒充免费；结果缓存复用会明确本次没有新调用。

2026-11-10隔离实测：公开咖啡样图（600×400，59,719字节）为499输入＋40输出token，估算`$0.000699`，约6秒完成；纯灰非食物样图为510输入＋31输出token、`$0.000665`，正确返回非食物。相同JPEG命中已完成结果缓存，新增token与费用均为0。使用正式Ali→SG→提供方通路、隔离数据库，没有创建正式进餐记录。样本只用于链路验证，不构成餐食/营养识别准确度验证。

这些不是每张图固定费用：实际图像/文本量、输出和计费模式会影响账单；输出限制为800token，不进行自动循环识别。

## 资料依据

- [Nutrition5k官方数据集](https://github.com/google-research-datasets/Nutrition5k)：真实营养标签包含称重与多视角/深度信息，不能把单张手机照片等同称重资料。
- [Mu等，餐食图像基础模型评估](https://pmc.ncbi.nlm.nih.gov/articles/PMC13401436/)：实测物理份量信息会影响营养估计，支持让用户补充/修正份量和使用范围；该研究不验证本应用当前模型的误差水平。
- 原CGM、活动与生理解释依据见[分析方法](CGM_ANALYSIS_METHOD.md)，不因精简文案而改变计算或凭空作出激素诊断。

## 接口与运行

`GET/POST /api/v1/events`、`POST /api/v1/events/delete` 保存标记；只有设备上传或分析能力令牌可写，组件只读令牌不可写。`POST /api/v1/meals/recognize` 创建任务，`GET`带requestId查询；识别同样要求写/分析能力。主应用保留分析能力，Widget配置不包含该能力。

照片专用Ali relay使用loopback18781，SG受限SSH转发本地18782；独立worker身份、客户端secret、持久计数与服务账户。既有血糖分析relay18779/隧道18778与教育项目服务保持独立。公开部署模板仅有占位，实际凭据不进仓库。
