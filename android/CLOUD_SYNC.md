# 手机云同步（0.2.0 / code 13）

手机与手表继续使用原来的包名、签名和数据协议。通知被接受后，先调用原 `BridgeService.updated()`，再把云端任务交给独立的单线程有界工作队列。SQLite 待上传队列按完整读数身份去重，允许同源时间的 A→B→A 更正；只有服务器明确确认整批 `accepted` 数量后才删除相应事件。上传与日报请求的失败均不覆盖手表连接状态。

## 配置

打开手机「血糖镜像 → 云同步 / 每日血糖观察」。可手动填写服务地址与设备上传令牌，或通过「从配置文件导入」选择以下 UTF-8 JSON：

```json
{"endpoint":"https://example.org:8443/ottai","token":"replace-with-device-upload-token"}
```

也兼容 `baseURL` 字段。地址必须为 HTTPS，支持路径前缀；请求拼接 `/api/v1/readings` 和 `/api/v1/dashboard`，不跳转到其他地址、不放宽证书/主机校验。设备令牌使用 Android Keystore 中的 AES-GCM 密钥加密保存，界面不会回显既有令牌。配置文件导入后可删除原文件；服务器模型 API 密钥不进入手机。没有配置时不发起云网络请求。

## 上传与恢复

- 每批最多 96 个队列事件；源时间、数值和趋势沿用通知中的合法数据，不改成上传时间。
- 初次配置或进程恢复可回补手机已有最多 24 条历史：未知趋势记 `?` 并带 `historical:true`，不会覆盖服务器已有的真实趋势或更正。最新完整缓存按正常事件恢复，可保留恰在进程退出前落入本机缓存的更正。
- HTTP 超时、服务端暂时失败等采用有上限的退避；连续 8 次失败后停止该次自动重试，网络重新连通、用户点击「立即同步」，或冷却 30 分钟后收到新读数可以恢复。认证/配置类 4xx 及 TLS 校验失败会暂停，需检查配置或手动重试，避免反复唤醒。
- 网络在线但无新读数时，运行中的桥接进程每约 5 分钟更新服务器日报缓存；系统 JobScheduler 另有网络条件下的 15 分钟恢复兜底，具体执行时间由 Android 决定。没有新增 CPU 唤醒锁。
- 数据库容量上限为 30,000 个未确认事件（按 5 分钟一条约 104 天）；到达上限后拒绝新入队并显示存储错误，不悄悄删除未确认数据。已有已确认身份去重记录保留 45 天。正常进程退出不清除 SQLite 队列；卸载或清除应用数据会删除它。

## 显示与验证

手机云页面展示最近 24 小时曲线、3.9/7.8 细线和观察范围、有效覆盖率/均值/极值/范围内比例，以及每日分析的生成日期、正文、限制和来源。至少 3 个历史日可用时，灰色曲线显示日内历史中位数；缺测超过 10 分钟不连接当前曲线。3.9–7.8 仅为用户观察范围，不作为糖前期诊断标准。

`tools/build_android.py` 运行原读取解析/表盘同步策略测试以及 `android/test/CloudPolicyTest.java`。新增测试覆盖 HTTPS/认证输入、有界退避、非法读数、重复与历史未知趋势抑制、同源更正返回原值；Android SQLite、Keystore、文件选择器及后台恢复仍需真机集成验收。
